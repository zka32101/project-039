# あんしんみち — 経路探索エンジン 技術検証プロトタイプ

`anshinmichi_code_handoff_v1_0.md` が実装着手前に必須とした技術検証スプリント
（1〜2週間相当）を、このリポジトリ内のNode.jsプロトタイプとして実施した結果一式。

## 検証項目と結論

| # | 項目 | 結論 |
|---|---|---|
| 1 | OSM道路データ取得→グラフ構築の処理時間 | 49ノード規模で1ms未満。**ただし実データ・広域では未検証（下記「既知の制約」参照）** |
| 2 | 建物データ×太陽角度の影スコア事前計算バッチ | 49ノード/24建物規模で約10ms。アルゴリズムは動作確認済み |
| 3 | 重み付き最短経路（Dijkstra）のレスポンスタイム | 200回反復で平均0.1ms・最大1.6ms。実用速度を大きく下回る |

詳細な数値は [`RESULTS.md`](./RESULTS.md)（`npm run benchmark` で再生成可能）を参照。

追加で、バックログ「実データでの経路探索再検証」対応として、より大きな合成グリッド
（デフォルト60x60=3600ノード）での再検証を [`RESULTS_LARGE.md`](./RESULTS_LARGE.md)
（`npm run benchmark:large` で再生成可能）に記録した。要点:

- グラフ構築・経路探索（Dijkstra）は3600ノード規模でも実用速度（数百ms以内）に収まる
- 影スコア事前計算バッチは、建物群の空間インデックス化による絞り込み導入後、3600ノード規模で
  約350ms（導入前は同規模で約1秒）。素朴なO(エッジ数×建物数)の総当たりから改善したが、
  絞り込み半径は「最も高い建物」基準の上限値のため、建物高さの分布に偏りが大きい実データでは
  効果が薄れる可能性がある（`src/shadowScore.js`参照）
- 最近傍ノード探索は、実データ規模（1都市分）に近い4万ノードの専用データセットで比較すると、
  空間インデックス（`src/spatialIndex.js`）導入により高速化する（数千ノード程度では差が
  測定誤差に埋もれるため、この比較のみ別データセットで実施）

## 既知の制約（実環境での再検証が必須な点）

1. **Overpass APIへの実疎通は未検証。** このサンドボックス環境は外向きネットワークが
   プロキシでブロックされており（`overpass-api.de` へのCONNECTが403）、`src/fetchOsmData.js`
   は実装済みだが実行できていない。データ構造・レートリミット対応・タイムアウト処理は
   コードレビューベースの実装に留まる。
2. **検証データは合成データ（最大でも60x60=3600ノードグリッド、東京駅周辺を模した規模・密度）。**
   実際の1都市（数万〜数十万ノード規模）でグラフ構築・影スコア計算がどうスケールするかは
   依然として未検証（`RESULTS_LARGE.md`はあくまで規模を上げたときの傾向確認）。影スコア計算・
   最近傍ノード探索はいずれも`src/spatialIndex.js`による絞り込みを導入済みだが、建物高さの
   分布に偏りが大きい実データでは影スコア計算側の効果が薄れる可能性がある（上記参照）。
3. **影判定アルゴリズムは簡易な2D近似**（建物中心からの方位角・距離ベースの判定）。
   建物の実際のフットプリント形状までは考慮していない。精度は本検証のスコープ外。

## 実装着手可否についての所見

- 3点の検証項目のうち、**アルゴリズムそのものは小規模データで正常に動作し、レスポンス速度も
  問題ない**ことを確認した。設計書Section7が懸念した「経路探索エンジンの実装難度」のうち、
  アルゴリズム設計・実装自体は現実的な難度に収まると判断できる。
- 一方で、**実データでのスケーラビリティ（Overpass疎通含む）は本検証で確認できていない**。
  これは個人開発の検証環境の制約によるもので、実際にはネットワーク制限のない環境で
  1都市分のデータを使った再検証を行うべき。
- 上記を踏まえ、**Flutterアプリ側の実装（Aha Moment動線）は先行して着手可能**と判断。
  ただし本番の`RouteSearchService`（Cloud Functions）実装時には、このプロトタイプの
  `src/`配下のロジックをベースに、広域データでの負荷試験を必ず挟むこと。

## 構成

```
src/
  fetchOsmData.js   // Overpass APIからの道路・建物データ取得（未疎通・実装のみ）
  geo.js            // 距離計算等の共通ユーティリティ
  sunPosition.js    // 太陽位置（方位角・高度角）計算
  buildGraph.js     // 道路網→グラフ構築
  shadowScore.js    // 建物×太陽角度→影スコア事前計算バッチ
  routeSearch.js    // 重み付きDijkstra経路探索
  snapToRoad.js     // 投稿UIの軌跡→道路区間スナップ（設計書Step5.5対応）
  minHeap.js         // Dijkstra用の優先度付きキュー
  benchmark.js       // 検証項目1〜3を一括計測しRESULTS.mdを生成
  benchmark_large.js // 大規模合成データでの再検証 → RESULTS_LARGE.mdを生成
  spatialIndex.js    // 最近傍ノード探索・影スコア計算の建物絞り込みで使う空間インデックス
                     // （functions/src/と同一）
fixtures/
  generate_sample.mjs       // 合成グリッドデータ生成スクリプト（49ノード）
  generate_large_sample.mjs // 大規模合成グリッドデータ生成スクリプト（デフォルト60x60）
  tokyo_sample.json         // 生成済み検証用データ（49ノード/84エッジ/24建物）
test/                  // unit tests（node --test）
```

## 実行方法

```bash
npm install   # 依存パッケージ無し（Node.js標準機能のみで完結）
npm test              # unit test（23件）
npm run benchmark     # 検証項目1〜3を計測 → RESULTS.md を再生成
npm run benchmark:large  # 大規模合成データでの再検証 → RESULTS_LARGE.md を再生成
npm run fetch:sample  # fixtures/tokyo_sample.json を再生成（合成データ）
```
